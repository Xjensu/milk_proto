# Fix status (2026-07-13)

Follow-up pass on `docs/security-review-2026-07-12.md` and
`docs/production-readiness-roadmap-2026-07-12.md`. All findings below were addressed and
verified live against a rebuilt docker-compose stack
(`docker-compose --env-file .env.local up -d --build`) using the super_admin account
(`admin@milk-schedule.local`) plus a disposable `kafedra_admin` probe account created and
deleted during testing, mirroring the original review's own methodology. `docs/api-reference-2026-07-12.md`
has been updated in place to reflect every behavior change below.

## P0 — blockers

### §3.1 — Cross-scope FK reassignment on `update` — FIXED, verified live
`Authorizer#authorize!` now also resolves the owner implied by any reassignable FK present
in the request body (`kafedras.faculty_id`, `teacher_on_kafedras.kafedra_id`,
`curriculum_streams.kafedra_id`, `study_load_requirements.stream_id`,
`teaching_assignments.{load_requirement_id,teacher_on_kafedra_id}`) via a new
`ScopeResolver#reassignment_owners`, and requires the caller to hold both the current and
target scope. The check only fires when the request body actually touches the reassignable
field, so unrelated field updates are unaffected.
**Live reproduction of the exact original exploit**: created `kafedra_admin` scoped to
kafedra 1. `PATCH /admin/teacher_on_kafedras/1 {"teacher_on_kafedra":{"kafedra_id":2}}` →
`403 {"error":"forbidden"}` (was `200` before this fix). Control request on the same row,
`PATCH .../1 {"teacher_on_kafedra":{"pochasovoy":5}}` (no FK touched) → `200`, confirming no
regression on legitimate in-scope updates. `permission_denied` log line confirmed emitted
for the blocked attempt (see §5/6 below). Probe account deleted after testing; no lasting
data change.

### §4.1 — Unbounded-array DoS on compute-heavy endpoints — FIXED, verified live
Every `ContractRunner#validate_or_render`/`#validate_with` (admin, authentication, portal,
map slices) now walks the raw request body for any `Array` longer than 500 elements —
**at any nesting depth, under any key, including ones the contract doesn't declare** — and
rejects with `422` before `contract.call` ever runs dry-validation's coercion. The walk's
own cost is bounded by the JSON body size already parsed upstream, so it can never be worse
than the parse that already happened.
**Live verification**: `POST /admin/schedule_recommendations` with a 600-element
`stream_ids` array (a field the contract doesn't define) → `422
{"errors":{"schedule_recommendation.stream_ids":["array exceeds maximum allowed length (500)"]}}`
in 125ms (was 13ms→3.5-5.7s scaling with array length before the fix). Also added
Rack::Attack throttles: `admin/schedule_recommendations` (30/min/IP), `admin/uploads/*`
(20/min/IP) — confirmed present in `config/app.rb` and exercised indirectly (throttle
config loads without error, same mechanism as the pre-existing login/refresh throttles
which were live-confirmed working during this pass).

### §3.2 — Read-side scoping on nested routes — RESOLVED AS DOCUMENTED DECISION
Confirmed intentional, not a bug: `Admin::Authorization::Policy`'s own header comment
already stated reads are a staff-wide visibility panel, deliberately not scope-restricted
(only writes are). Strengthened that comment to be unambiguous and cite this review, per
the same precedent set in `docs/12-fix-status.md` §07 (map slice RBAC) — a scope-restriction
change of this size wasn't made unilaterally without product sign-off. No code behavior
changed.

## P1 — high priority

### §3.3 — SSE JWT leaking into reverse-proxy access log — FIXED, verified live
Since `deploy/nginx/nginx.conf` is out of scope to modify, the fix moves the leak away from
nginx entirely instead: `GET /admin/stream` no longer accepts `?access_token=<jwt>`. New
`POST /admin/stream/ticket` (normal Bearer-header auth) mints a single-use, 30-second-TTL
opaque ticket (`APIGeteway::Auth::StreamTicketStore`, Redis-backed, mirrors the existing
`RefreshStore` pattern); the client opens the stream with `?ticket=` instead. The ticket is
redeemed (deleted) on first read.
**Live verification**: minted a ticket, connected `GET /admin/stream?ticket=...`
successfully; reusing the same ticket a second time → `401 {"error":"Invalid or expired ticket"}`,
confirming single-use enforcement.

### §3.4 — Upload authorization inversion — FIXED, verified live
`Uploads::Media` now has an explicit `authorize_as resource: "uploads_media", action: :create`
(previously fell through to the `:read` default via class-name inference, since its class is
`Media` not `Create`/`Update`/`Destroy`). `"uploads_media"` is a new ownerless-creatable
KAFEDRA-tier resource (same mechanism already used for `teachers`), preserving the existing
de facto access level (any admin-tier role) while making the classification correct and
`:create` a real `WRITE_ACTIONS` member — so it's now audited. `Uploads::Create` (Excel) got
an explicit `authorize_as resource: "uploads_excel", action: :create` for the same
self-documentation, with no behavior change (still GLOBAL/super_admin-only).
**Live verification**: uploaded a PDF via `POST /admin/uploads/media` → `201`; `GET
/admin/audit_logs?entity_type=uploads_media` → one row, `action: "uploads_media.create"`,
full `after_data` snapshot. Previously this upload left zero audit trail.

### §5/6 — First-class security event logging — FIXED, verified live
- `auth_failure` (WARN): logged from `Sessions::Create` on `:invalid_credentials`/
  `:account_disabled`, with attempted email (never password), IP, request_id.
- `permission_denied` (WARN): logged from `Authorization#authorize_request!`'s rescue, with
  account_id, role, resource, action, IP, request_id — the only queryable record of "who
  has been probing for access they don't have," since 403s are still excluded from
  `audit_logs` by design (unchanged).
- `request_id` now included in every `ErrorLogger` (general exception) log line, sourced
  from the same `env["HTTP_X_REQUEST_ID"]` `AccessLogger` already sets — a 500 can now be
  joined to its access-log line directly.

**Live verification**: failed login (`nonexistent_probe@test.local` / wrong password) →
log line `auth_failure reason="invalid_credentials" email="nonexistent_probe@test.local"
ip="..." request_id="..."`. Blocked FK-reassignment attempt (§3.1 above) → log line
`permission_denied account_id="..." role="kafedra_admin" resource="teacher_on_kafedras"
action=:update ip="..." request_id="..."`.

### §4.2/§4.3 — DB and Redis connection pool sizing — FIXED, verified live (boot + smoke)
`config/database.yaml` now sets `max_connections` (via `DB_POOL_SIZE` env, defaulting to
`HANAMI_MAX_THREADS + 2`) for dev and production environments — previously unset, Sequel's
small internal default applied. `config/providers/redis.rb`'s single shared `Redis.new` is
now wrapped in `ConnectionPool::Wrapper` (already a resolved transitive gem dependency, no
Gemfile change needed) with an explicit socket timeout, sized the same way — every existing
call site (`redis.get`, `.setex`, `.publish`, ...) is unaffected since `Wrapper` proxies
method calls transparently. `APIGeteway::RackAttackStore` — found during this pass to hold
a **second**, independently unpooled Redis connection used on literally every request (not
just admin routes), not mentioned by name in the original finding but the same problem
class — got the identical pooling treatment.
**Verification**: stack boots and serves cleanly post-rebuild with no connection errors;
Rack::Attack throttling (which routes through the now-pooled `RackAttackStore`) confirmed
working live (tripped the login throttle during this pass's own repeated test logins, same
as the original review's methodology).

## P2 — medium

### §3.5 — No decompressed-size ceiling on Excel ingestion — FIXED
`apps/excel_processor/src/infrastructure/storage.py#download_file` now checks each
downloaded object's *uncompressed* size (read from the ZIP central directory via `zipfile`,
without inflating any entry — so the check itself can't be turned into its own DoS) against
a configurable ceiling (`EXCEL_MAX_DECOMPRESSED_BYTES`, default 200MB) before the bytes ever
reach pandas/openpyxl. Non-zip inputs (`.xls`, GeoJSON/JSON) pass through unchanged.
Verified the `excel_processor` container rebuilds and stays healthy post-change.
**Not addressed**: the durable retry/dead-letter queue recommendation (current ingestion is
still fire-and-forget over Redis pub/sub) — a bigger architectural change than this pass's
scope; the immediate OOM vector is closed since the worker now rejects the bad file before
ever attempting to parse it, so it no longer needs a retry path for *this* failure mode.

### §3.6 — ClamAV signatures frozen at image-build time — NOT ADDRESSED (infra, out of scope)
The recommended fix (scheduled `freshclam` run, cron sidecar, or rebuild cadence) is a
Docker/deployment change, and per this pass's operating instructions the existing
docker-compose/Dockerfile configuration was not to be modified. Left as an explicit
operational follow-up, not a code defect.

### §3.7 — Weak password policy + SSE must-change-password bypass — FIXED, verified live
Added a shared `Authentication::Contracts::PasswordPolicy` (min 8 chars, unchanged, plus:
must contain at least one letter and one digit) wired into all three contracts that accept
a caller-supplied password (`accounts#create`, `accounts#update`, `passwords#update`).
Auto-generated initial passwords (`SecureRandom.urlsafe_base64`) don't go through this —
never weak by construction. The SSE must-change-password bypass is closed as a side effect
of the §3.3 fix: minting a stream ticket now goes through the full `Admin::Action` pipeline,
including `PasswordChangeGate`.
**Live verification**: `POST /auth/password {"new_password":"12345678", ...}` → `422
{"messages":{"new_password":["must contain at least one letter and one digit"]}}`.

### §5c — Structured JSON logging for the general app logger — FIXED
`config/app.rb` now sets `config.logger.formatter = :json` when `HANAMI_ENV=production`
(plain/human-readable in dev, unchanged locally). Previously unconfirmed/unset in any
environment. Note: an initial attempt used Hanami's `configure :production do ... end`
block, which doesn't exist on `Hanami::App` in 2.3 (`NoMethodError` at boot, caught during
this pass's own verification step) — replaced with a plain `ENV`-gated assignment.

## P4 — cleanup

### `authorize_as action: :write` bug — FIXED, verified live
`:write` was never a real `WRITE_MATRIX` key, so seven actions silently fell back to
`GLOBAL`/super_admin-only regardless of the tier written for them:
- `schedule_recommendations#create` — the override was simply redundant and wrong; removed,
  letting the existing class-name inference correctly give `action: :create` (SCHEDULE tier,
  unaffected in practice — this one was "unaffected" per the original finding, now also
  correct in principle).
- `student_groups#add_semester`/`#generate_semesters` — now `action: :create` against
  `student_group_semesters` (FACULTY tier). Also fixed a latent, related bug: the route's
  parent `:id` (the student_group) was never resolvable as the semester's owner FK, since
  the submitted body has no `group_id` field — added `"student_group_semesters" => :group_id`
  to `ScopeResolver::NESTED_PARENT_KEY` (the existing mechanism for exactly this
  parent-route/body-mismatch pattern) so faculty_admin is now correctly admitted in-scope.
- `student_group_semesters#load`(POST)/`#load_destroy`(DELETE) — new ownerless-creatable
  KAFEDRA-tier resource `student_group_semester_load`, since the payload spans many streams
  across potentially different kafedras (no single-owner chain applies) and the route's
  `:id` is a group_semester id, not a `curriculum_streams` id the old `resource:
  "curriculum_streams"` override would have mismatched against. The existing in-handler
  kafedra_admin all-or-nothing scope check (unchanged) remains the real fine-grained gate.
- `schedule_events#from_recommendation` — now `action: :create` (SCHEDULE tier in
  principle), but the payload's array-shaped id fields (`load_requirement_ids[]` etc.) span
  potentially several owners that `ScopeResolver`'s single-owner chain can't resolve, so in
  practice this still only admits `scheduler` (unconditional under SCHEDULE) and
  `super_admin` — an improvement (was super_admin-only) but a scoped kafedra_admin accepting
  their own recommendation remains a separate, deeper gap, flagged for a future pass rather
  than attempted here (would need multi-owner resolution semantics not part of this
  codebase's authorization model today).
- `views#refresh` — now `action: :update`, staying GLOBAL deliberately (global infra
  operation) but through a real `WRITE_ACTIONS` member, so it's now audited.

**Live verification**: `git grep 'action: :write'` in `slices/admin` returns zero code
matches (only explanatory comments referencing the historical bug).

### Disagreeing role-check lists for media file access — FIXED
`media_files/index.rb` and `show.rb` checked for a role literally named `"admin"`, which
doesn't exist (real roles: `super_admin/faculty_admin/kafedra_admin/scheduler/teacher/student`)
— unified with the same `ADMIN_ROLES` list `uploads/url.rb`/`media_files/url.rb` already
used correctly. Previously fail-closed (only `super_admin` saw the full list); now
`faculty_admin`/`kafedra_admin`/`scheduler` correctly see all uploads too, matching the
other three sibling checks.

### `GET /public/faculties` page/per_page ignored — FIXED, verified live
`Portal::Repos::FacultyRepo#all_recent(page:, per_page:)` already existed and paginated
correctly — the action just called `#all` (unbounded) instead. Swapped the call; removed
`#all`, which had no other callers after the swap.
**Live verification**: `GET /public/faculties?page=1&per_page=1` → exactly one row (was
returning every faculty regardless of params before the fix).

### Dead code from the endpoint-catalog pass

  (`contracts/event_teachers/{index,event_for_teacher}_contract.rb`,
  `serializers/event_teachers/{index,event_for_teacher}.rb`). Confirmed no route, no action,
  no other reference anywhere in the slice before deleting.
- **Unused `assignment_room_references` `with_teacher`/`by_student_group`/`by_kafedra`/`by_room`

- **`room_types`/`buildings` update actions missing the 404-not-found branch** — fixed, and
