# MMP implementation/specification reconciliation notes

**Inspection date:** 2026-09-11  
**Scope:** read-only comparison of the implementation, vectors, tests, and the
numbered MMP documents. This reconciliation did not modify the normative
documents under `docs/spec/`; the table records the selected implementation
behavior and its evidence.

## Evidence boundary

- Vectors: `implementation/mesh-milk/vectors/coverage.json` declares 39
  entries. It covers bundle classes 0-5, canonical/TLV negatives, lifetime
  reset, envelope and frame registry (including HS, ID_PROOF, CREDIT, all
  RBSR frames, WANT, BUNDLE/BUDGET, blobs, friendship, ERROR/CLOSE), claim,
  receipt MAC, prekey agreement, and the RBSR fingerprint.
- Independent reader coverage is in `mmp-cli/src/conformance.rs`; production
  round trips/rejections are exercised by the type/core/crypto tests.
- Focused run on this checkout:
  `cargo test --locked -p mmp-types -p mmp-crypto -p mmp-core -p mmp-router
  --all-targets -- --test-threads=1`  -  139 passed, 0 failed; and
  `cargo test --locked -p mmp-node --lib -- --test-threads=1`  -  198 passed,
  0 failed. `RUSTFLAGS=-C debuginfo=0` was used to avoid the known Windows
  MSVC PDB linker failure; this is host test evidence, not device evidence.
- Existing worktree changes were preserved. This note is an internal release
  artifact and does not revise a normative document.

## Findings to carry into release review

1. Treat encrypted ID_PROOF and single-pass D3 as explicit MMP/1 behavior only
   after the public document errata are approved; keep the current tests and
   vectors as the implementation contract in the interim.
2. Do not mark group control complete until production messages carry an
   authenticated administrator anchor, epoch floor/merge rule, late-join
   policy, and replay/retention tests.
3. Do not mark file transfer confidential until symbols are generated from an
   authenticated file-level ciphertext with a specified key/nonce/context
   binding. Current Merkle proofs establish integrity and attribution only.
4. Keep BLE/profile status at partial until physical evidence and platform
   adapter gates are attached; codec tests and an evidence-manifest validator
   do not substitute for a two-host radio run.
