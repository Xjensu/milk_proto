# Transport Close Feedback (Implementation Contract)

Status: implementation contract; no wire-format change.

## Problem

The protocol specification makes session admission and teardown local policy. A
node may therefore reject a physical `LinkUp`, close a session after malformed
input, or retire a link after bounded outbox overflow. Previously these local
decisions removed the Rust session but gave the BLE host no action to close the
underlying connection. A stale physical link could then consume radio and host
resources, and queued frames could survive a `LinkDown`.

## Contract

`mmp-node::Node` now exposes a bounded, transport-local close queue:

```text
Node::poll_close() -> Option<LinkId>
```

The queue is populated for:

1. a new `LinkUp` denied by the tier session cap;
2. a `SessionEvent::Closed` generated by the session engine;
3. an outbox overflow that retires the affected link.

Duplicate `LinkUp` events for an existing session do not request a close. A
physical `LinkDown` purges all queued frames for that link and cancels any
unconsumed close action for it.

The queue is capped at 64 link IDs and coalesces duplicates. Hosts must drain it
after every injected TAL event and clock tick. `close_actions_dropped()` exposes
queue saturation as an operational diagnostic; it is not a protocol delivery
result.

## Host integration

- Central BLE: call `BleCentral::hangup(link)` for every `poll_close()` result.
- Linux peripheral BLE: call `PeripheralRole::close_link(link)`; this retires
  the local endpoint and emits the reserved transport `LinkDown` event.
- UniFFI/mobile: call `MmpNode::poll_close()`, close the platform BLE/GATT link,
  then call `MmpNode::link_down(link)` when the platform reports the physical
  teardown. `poll_send()` must run only after close actions have been drained.

This queue is deliberately outside `TalEvent` and outside all encoded frames.
It does not alter the frozen protocol specification or create a new peer-visible
message.

## Verification

The node tests cover tier denial, duplicate admission, malformed-session close,
outbox overflow, stale-frame purge on `LinkDown`, and action visibility. The FFI
test exercises the mobile-facing denial path. Peripheral and CLI builds verify
that both host roles expose a close seam.

## Remaining platform work

Android and iOS integration layers still need to wire `poll_close()` to their
native GATT disconnect APIs and report the resulting `link_down` callback. A
hardware run must confirm that the OS actually releases the connection and that
the host drains the bounded queue before saturation.
